# 2026-05-12 工作日志

## DataAgent 性能优化：baostock 批量登录

**问题**：DataAgent 拉取全市场数据时，每只股票的 `sync_one_stock()` 都单独 `bs.login()` / `bs.logout()`，后台打印大量 login/logout 信息，拖慢速度。

**改动**：
1. `core/sync.py:219` — `sync_one_stock()` 新增 `auto_login: bool = True` 参数，为 `False` 时不自行管理登录会话。
2. `agents/data_agent.py:115` — `_run_sync()` full 模式下先 `bs.login()` 一次，循环内调用 `sync_one_stock(..., auto_login=False)`，最后 `bs.logout()`。

**效果**：全市场同步时 baostock 只登录/登出各一次，消除 N 次重复登录开销。

## BacktestAgent KeyError: 'win_rate' 修复

**问题**：`backtest_agent.py:59` 汇总报告时访问 `r["win_rate"]`，但 fusion 分支返回的报告字段是 `win_rate_5d` / `avg_return_5d`，导致 `KeyError`。此外若某只股票回测出错（status=error），报告也没有这两个字段。

**改动**：
1. `backtest_agent.py` fusion 分支：返回字典增加 `win_rate` 和 `avg_return` 字段（与 v4 分支对齐），同时保留 `win_rate_5d` / `avg_return_5d` 作为补充。
2. 汇总统计：只对有 `status="ok"` 的报告计算平均值，跳过 error/no_signals 的条目。

## Dashboard "流水线启动" 日志重复打印修复

**问题**：Dashboard 前端轮询 `/api/agents/status` 时，每次检测到 `pipeline_running=true` 都会调用 `setPipelineRunning(true)`，而该函数每次都打印 `addPipelineLog('warn', '流水线启动...')`，导致日志里出现大量重复的"流水线启动..."记录。

**改动**：
1. `dashboard.html:765` — `setPipelineRunning()` 开头增加状态变化判断：`if (isRunning === running) return;`，状态未变时直接返回，不重复打印日志。
2. `agent-dashboard.html:367` — 同样增加状态变化判断。

**效果**：流水线运行期间，前端轮询不再重复打印"流水线启动"日志，只在状态真正变化时记录一次。

## 流水线日志可读性增强

**问题**：`print()` 没有 `flush=True`，Python 缓冲 stdout，导致日志不实时；各阶段之间只有注释没有打印，难以判断当前在哪个步骤。

**改动**：
1. `orchestrator.py` — 所有 `print()` 加 `flush=True`；每个 Stage 开始前打印 `▶ 当前阶段: Stage N/4  XXX(AgentName)` 并带分隔线；`_run_agent()` 内新增心跳线程，Agent 运行每30秒打印 `⏳ XXX 执行中... (已运行 Xs)`，Agent 结束后自动停止心跳（try/finally 保护）。
2. `agents/data_agent.py` — 同步进度打印加 `flush=True`。
3. `agents/signal_agent.py` — 扫描进度打印加 `flush=True`。

**效果**：日志实时出现，阶段分隔清晰，长时间运行的 Agent 有心跳提示不会以为卡死。
