## 一、问题诊断总结

### 1.1 性能瓶颈

### 2.2 异步任务规范化（去 Celery 过度设计）

**问题**: `routes/sync.py`、`routes/backtest.py`、`routes/strategy.py` 都用 `threading.Thread(daemon=True)` + 模块级 dict 追踪进度。无任务 ID、无并发防护、重启丢状态。`recalc_all_scores` 更是在请求线程同步执行。

**方案**: 用 `concurrent.futures.ThreadPoolExecutor` + UUID 任务 ID + 简单状态存储替代裸线程。不需要引入 Redis/Celery。

```python
# core/task_queue.py
import uuid
import time
from concurrent.futures import ThreadPoolExecutor
from threading import Lock

_executor = ThreadPoolExecutor(max_workers=4)
_lock = Lock()
_tasks: dict[str, dict] = {}

def submit_task(fn, *args, **kwargs) -> str:
    """提交异步任务，返回任务 ID"""
    task_id = str(uuid.uuid4())[:8]
    with _lock:
        _tasks[task_id] = {"status": "pending", "progress": 0, "message": "", "started_at": time.time()}

    def _wrap():
        with _lock:
            _tasks[task_id]["status"] = "running"
        try:
            result = fn(*args, progress_callback=lambda p, m: _update(task_id, p, m), **kwargs)
            with _lock:
                _tasks[task_id]["status"] = "success"
                _tasks[task_id]["result"] = str(result)
        except Exception as e:
            with _lock:
                _tasks[task_id]["status"] = "error"
                _tasks[task_id]["message"] = str(e)

    _executor.submit(_wrap)
    return task_id

def _update(task_id: str, progress: int, message: str):
    with _lock:
        if task_id in _tasks:
            _tasks[task_id]["progress"] = progress
            _tasks[task_id]["message"] = message

def get_task_status(task_id: str) -> dict | None:
    return _tasks.get(task_id)

def cleanup_old_tasks(max_age_seconds: int = 3600):
    """清理超过1小时的已完成任务，防止内存泄漏"""
    now = time.time()
    with _lock:
        expired = [tid for tid, t in _tasks.items()
                   if t["status"] in ("success", "error")
                   and now - t.get("started_at", 0) > max_age_seconds]
        for tid in expired:
            del _tasks[tid]
```

### 2.3 简单查询缓存（去 Redis 过度设计）

**问题**: 重复查询不频繁变化的数据（最新交易日、股票列表等）。

**方案**: 使用 `functools.lru_cache`。对无参数函数（如 `get_latest_score_date`）直接用，对有参数函数（如 `get_daily_scores(page, per_page)`）用 `ttl_cache`。SQLite 单用户场景不需要 Redis。

> **注意**: TTL 缓存用 `str(args)` 做 key 有隐患——传入 DataFrame 或 list 时 `str()` 产生的字符串巨大且不可靠（空格差异）。改用 `pickle.dumps` + hash，或对简单场景直接用 `functools.lru_cache(maxsize=128)`。

```python
# utils/cache.py
import time
import hashlib
import pickle
from functools import wraps, lru_cache

def ttl_cache(ttl_seconds: int = 60):
    """带 TTL 的内存缓存装饰器。适合单进程 SQLite 场景，不需要 Redis。"""
    def decorator(func):
        _cache = {}
        _expiry: dict[str, float] = {}

        @wraps(func)
        def wrapper(*args, **kwargs):
            key = hashlib.md5(pickle.dumps((args, kwargs))).hexdigest()
            now = time.time()
            if key in _cache and now < _expiry.get(key, 0):
                return _cache[key]
            result = func(*args, **kwargs)
            _cache[key] = result
            _expiry[key] = now + ttl_seconds
            return result

        wrapper.cache_clear = lambda: (_cache.clear(), _expiry.clear())
        return wrapper
    return decorator


# 无参数函数直接用 lru_cache（最简单）
@lru_cache(maxsize=1)
def get_latest_score_date():
    with get_conn() as conn:
        row = conn.execute("SELECT MAX(trade_date) FROM stock_score").fetchone()
        return row[0]

# 有参数函数用 ttl_cache
@ttl_cache(ttl_seconds=300)
def get_daily_scores(trade_date: str, page: int, per_page: int):
    with get_conn() as conn:
        offset = (page - 1) * per_page
        rows = conn.execute(
            "SELECT * FROM stock_score WHERE trade_date = ? ORDER BY score DESC LIMIT ? OFFSET ?",
            (trade_date, per_page, offset)
        ).fetchall()
        return [dict(r) for r in rows]
```

### 3.1 提取公共 `_sanitize` 函数

**方案**:

```python
# utils/serialization.py
import math
from typing import Any

def sanitize_numeric(obj: Any) -> Any:
    """递归替换 NaN/Inf 为 None，numpy 类型转 Python 原生"""
    if isinstance(obj, float):
        if math.isnan(obj) or math.isinf(obj):
            return None
        return obj
    if hasattr(obj, "item"):  # numpy scalar → Python native
        return sanitize_numeric(obj.item())
    if isinstance(obj, bytes):
        return obj.decode("utf-8", errors="replace")
    if isinstance(obj, dict):
        return {k: sanitize_numeric(v) for k, v in obj.items()}
    if isinstance(obj, list):
        return [sanitize_numeric(v) for v in obj]
    return obj
```

各路由文件改为 `from utils.serialization import sanitize_numeric as _sanitize`，删除私有定义。

## 五、页面交互优化

### 5.1 Tab 切换状态保持

```javascript
const TabStateManager = {
    states: new Map(),
    MAX_AGE: 5 * 60 * 1000, // 5分钟

    save(tabName, state) {
        this.states.set(tabName, {
            ...state,
            scrollTop: document.querySelector('.content')?.scrollTop || 0,
            timestamp: Date.now()
        });
    },

    load(tabName) {
        const s = this.states.get(tabName);
        if (s && Date.now() - s.timestamp < this.MAX_AGE) return s;
        this.states.delete(tabName);
        return null;
    }
};

async function switchTab(tab) {
    const cached = TabStateManager.load(currentTab);
    if (cached) {
        // 保存当前 DOM 快照
        TabStateManager.save(currentTab, { html: document.getElementById('content').innerHTML });
    }

    currentTab = tab;
    document.querySelectorAll('.nav-item').forEach(t => t.classList.remove('active'));
    document.querySelector(`.nav-item[onclick*="${tab}"]`)?.classList.add('active');

    const cachedNew = TabStateManager.load(tab);
    if (cachedNew) {
        document.getElementById('content').innerHTML = cachedNew.html;
        document.querySelector('.content').scrollTop = cachedNew.scrollTop;
    } else {
        await loadTab(tab);
    }
}
```

> **注意**: 当前项目中 `switchTab` 是同步函数，`loadTab` 返回 Promise 但未 await，异常会被吞掉。改为 `async function switchTab` 后，`onclick` 调用不会自动 await，建议在 HTML 中改为 `onclick="switchTab('xxx').catch(e => showToast(e.message, 'error'))"` 或在 `switchTab` 内部 try-catch。

### 5.2 搜索防抖（增强现有实现）

### 5.3 fetchJSON 支持 AbortSignal

**问题**: 当前 `fetchJSON` 不接收 signal，Tab 切换时旧请求无法取消。

**修复**:

`fetch` API 原生支持 `AbortSignal`，只需在 `opts` 中传入 `signal` 即可，`fetchJSON` 本身无需额外处理。只需加默认值防御 `opts` 为 `undefined` 的情况：

```javascript
// 修改后 — 仅加默认值，fetch 原生透传 signal
async function fetchJSON(url, opts = {}) {
    const resp = await fetch(url, opts);
    if (!resp.ok) throw new Error(resp.statusText);
    return resp.json();
}
```

调用方统一加 signal：

```javascript
// 请求管理器
const RequestManager = {
    controllers: new Map(),

    async fetch(key, url, opts = {}) {
        this.cancel(key);
        const ctrl = new AbortController();
        this.controllers.set(key, ctrl);
        try {
            return await fetchJSON(url, { ...opts, signal: ctrl.signal });
        } finally {
            this.controllers.delete(key);
        }
    },

    cancel(key) {
        this.controllers.get(key)?.abort();
        this.controllers.delete(key);
    },

    cancelAll() {
        this.controllers.forEach(c => c.abort());
        this.controllers.clear();
    }
};

// loadTab 中统一使用
async function loadTab(tab) {
    const container = document.getElementById('content');
    const data = await RequestManager.fetch(tab, API + getTabEndpoint(tab));
    if (data) renderTab(tab, data, container);
}

// switchTab 中取消旧请求
```

```javascript
class TimerManager {
    constructor() { this.timers = new Map(); }

    setInterval(key, fn, delay) {
        this.clear(key);
        this.timers.set(key, setInterval(fn, delay));
    }

    setTimeout(key, fn, delay) {
        this.clear(key);
        this.timers.set(key, setTimeout(() => { fn(); this.timers.delete(key); }, delay));
    }

    clear(key) {
        const id = this.timers.get(key);
        if (id != null) { clearInterval(id); clearTimeout(id); this.timers.delete(key); }
    }

    clearAll() {
        this.timers.forEach(id => { clearInterval(id); clearTimeout(id); });
        this.timers.clear();
    }
}
```

### 6.2 数据库操作最佳实践

SQLite 单用户场景不需要连接池（SQLAlchemy 连接池对 SQLite 无益）。但需要：

```python
# core/connection.py — 从 db.py 提取
import sqlite3
from contextlib import contextmanager

DB_PATH = "core/quant.db"

@contextmanager
def get_conn():
    conn = sqlite3.connect(DB_PATH)
    conn.row_factory = sqlite3.Row
    conn.execute("PRAGMA journal_mode=WAL")
    conn.execute("PRAGMA foreign_keys=ON")
    try:
        yield conn
        conn.commit()
    except Exception:
        conn.rollback()
        raise
    finally:
        conn.close()
```

**注意**: SQLite 写操作是串行的。`recalc_all_scores` 应使用批量 `executemany` + 单个事务，而非逐行 `execute` + 多次提交。示例：

```python
# core/sync.py — 批量写入评分（替代逐行 execute + commit）
def batch_upsert_scores(scores: list[dict]):
    """批量写入评分，单事务提交"""
    with get_conn() as conn:
        conn.execute("BEGIN TRANSACTION")
        conn.executemany("""
            INSERT INTO stock_score (code, trade_date, score, volume_score,
                                     trend_score, reversal_score, cap_score)
            VALUES (:code, :trade_date, :score, :volume_score,
                    :trend_score, :reversal_score, :cap_score)
            ON CONFLICT(code, trade_date) DO UPDATE SET
                score = excluded.score,
                volume_score = excluded.volume_score,
                trend_score = excluded.trend_score,
                reversal_score = excluded.reversal_score,
                cap_score = excluded.cap_score
        """, scores)
        conn.commit()
```

## 九、风险与注意事项

1. **分页 API 前后端联动**: 分页参数需要前后端同步修改，建议先改 API 加分页，再改前端消费
2. **任务队列重启丢状态**: 内存存储重启清空是预期行为（by design），如有持久化需求后续加 SQLite 表
3. **虚拟滚动 + 搜索**: Clusterize.js 更新数据时需同步更新搜索过滤后的行集
4. **渐进实施**: 严格按优先级分批提交，每批可独立上线和回滚
5. **定时器全覆盖**: `syncPollTimer` 和 `pollBt`（回测轮询）都应纳入 TimerManager，避免遗漏
6. **不去做的事情**（有意排除）:
   - ~~Redis 缓存~~ — SQLite 单用户场景不需要引入外部中间件
   - ~~Celery 任务队列~~ — `ThreadPoolExecutor` 足够，复杂度不匹配
   - ~~SQLAlchemy 连接池~~ — SQLite 写操作串行，连接池无性能收益
   - ~~手写 VirtualTable~~ — 用 Clusterize.js，减少维护负担
   - ~~db.py 一次性拆 6 个 model~~ — 分两阶段，先提取 schema + connection
