## 1. 筹码峰是什么，补了哪个洞

筹码分布（成本分布）把每根 K 线的成交量当作「当日新增筹码」，按**三角形分布**撒到价格轴上；
历史筹码按当日换手率衰减。迭代后得到「持仓成本分布」，即筹码峰。派生出 6 个因子：

| 因子 | 含义 | 单变量最佳档 | 单变量最差档 |
|------|------|-------------|-------------|
| `winner` | 获利盘比例 | Q3 0.64~0.80 → +1.22% | Q5 >0.925 → +0.81% / 止损 37.3% |
| `conc` | 集中度 (P90-P10)/(P90+P10) | Q1 ≤0.167 → +1.26% / **止损 20.9%** | Q5 >0.367 → 止损 38.4% |
| `pressure` | 上方筹码占比 = 1-winner | 倒 U（Q1 最差 +0.81%） | — |
| `cost_ratio` | 筹码中枢/现价 | Q4 0.96~1.04 → +1.36% / 22.9% | Q1 <0.78 → +0.75% / 41.3% |
| `lock` | 低位锁仓度（现价×0.85 以下筹码占下方比） | Q2 0.17~0.38 → **+1.62% / 胜率 56.2% / PF 1.92** | Q5 >0.73 → +0.65% / 42.2% |
| `center_shift` | 筹码中枢 20 日移动 | Q1/Q2（不动或下移）→ +1.3~1.4% | Q4/Q5（上移）→ +0.73~0.84% |

**它补的洞**：现有策略全部是「价格/量能/趋势」派生——都在回答「价格走到哪了」。筹码分布回答的是
**「筹码在谁手里、成本多少」**，这是现有链路里完全空白的维度。尤其：

- `pure_bottom_v2` 的「回踩支撑」用 **MA20**（20 日收盘均价）代理，这是**时间平均值，不是真实成本**；
- `short_observe_bottom_min_ext ≥ 5.5%` 这个阈值门与 `short_ext_sort_desc` 互为替代的僵局
  （见 `strategy_params.py` 注释）——筹码结构可能正是它们粗粒度代理的那个东西。

## 2. 实现要点（`strategy/chip.py`）

**数值稳定性的关键**：朴素递推 `C[t] = C[t-1]*(1-h[t]) + new[t]` 需逐日 Python 循环，
2,652 只 × 1,300 日会跑到小时级。改用**块内解析展开**：

```
C[t] = E[t] * ( C_blk0 + Σ_{s<=t} new[s]/E[s] ),  E[t] = Π_{u<=t}(1-h[u])
```

块内走 `cumsum`，每 256 天真实递推一次重新锚定。**不分块的话**长历史下 `E[0]` 会下溢到 0，
`1/E[0]` 直接爆 inf——这是本模块唯一需要小心的陷阱。

**实测性能**：8 进程 × 96 秒算完 2,652 只 / 335 万行（单只 ~36ms）。

**踩过的坑（已在代码注释里标注）**：

1. `daily_price.turnover` **68.6% 的行为 0/空**，不能直接用 → 回退 `volume / circ_shares`
   （已验证：000651 2383 万股 / 55.15 亿股 = 0.432% ↔ 库 `turnover`=0.43，四只票全吻合）。
2. 低换手股筹码**几乎不衰减**：茅台换手 0.26%×0.65 = 0.17%/日 → 记忆期约 590 日，
   分布被摊平成「近三年成交的累积」、峰形消失 → 加 `decay_floor=0.003`（记忆期压到 ≤330 日）。
3. **Windows spawn**：`decay` 必须随 payload 传进子进程，main() 里的 global 赋值不会继承。
4. `circ_shares` 取当前快照 → 历史增发/解禁会使早年换手率有偏差（已知误差，见模块 docstring）。
5. 未做复权还原 → 除权跳空会留假「筹码断层」（用自算换手率已弱化该效应）。

**参数不敏感性**：`decay ∈ {0.35, 0.65, 0.85}` 三组结果**关键数字完全一致**
（止损率 20.9%/38.4%、lock Q2 +1.62%/56.2%、组合样本外 +0.81% 一字不差）。
说明筹码因子的**排序结构**稳定，不是调参调出来的。

## 3. 四道关卡（上线前必过）

### 关卡① 正交性 — 通过

| 因子 | Spearman vs ext | 判定 |
|------|----------------|------|
| winner +0.049 / conc +0.036 / pressure −0.049 / cost_ratio −0.037 / lock +0.078 / center_shift −0.052 | 全部 \|r\| ≤ 0.078 | **正交** |

### 关卡② 增量（控制 ext 分桶）— 收益不通过，风险通过

以 `conc` 最低 25% 档 vs 桶内基线（n=26,262）：

| ext 桶 | 桶内基线 | conc 最低25% | 收益价差 | 止损率变化 |
|--------|---------|-------------|---------|-----------|
| 桶1 [−0.001,0.019] | +0.93% / 止损 28.9% | +0.87% | **−0.06** | 28.9% → **20.9%** |
| 桶2 [0.019,0.032] | +0.94% / 止损 29.2% | +0.88% | **−0.06** | 29.2% → **21.3%** |
| 桶3 [0.032,0.118] | +1.41% / 止损 32.5% | +1.79% | **+0.38** | 32.5% → **24.2%** |

→ 收益增量 **2/3 桶为负**（不成立）；**止损率改善 3/3 桶一致**（−7~8pp，稳固）。

### 关卡③ 组合口径 — **过滤器方案否决，排序方案通过**

组合口径（每日 top3）才是最终判据，逐笔口径的池子平均会被 top-N 名额稀释。

**方案 A：当过滤器**（否决）

| 规则 | 全期 | 样本内 | 样本外 | 止损率 |
|------|------|--------|--------|--------|
| 基线（现线上） | +0.32% | −0.20% | +0.91% | 37.1% / 38.8% / 35.2% |
| `conc ≤ P20` | +0.65% | +0.51% | **+0.81%** ↓ | 25.7% |
| `lock ∈ [P20,P70]` | +0.60% | +0.45% | +0.76% ↓ | 34.2% |
| `lock适度 & conc≤P40` | +1.10% | +1.35% | **+0.80%** ↓ | 27.2% |

→ **样本外全部 ≤ 基线**。逐笔口径看着好（+1.38%），组合口径样本外全部失效。
另：逐月剔除贡献最大 2 月后增量从 +0.31% 塌缩到 **+0.09%**（单月依赖）。

**方案 B：当第一排序键**（通过）

| 排序键 | 全期 | 样本内 | 样本外 | 止损率（全期） |
|--------|------|--------|--------|--------------|
| 基线 `ext↑, fusion↓` | +0.32% | −0.20% | +0.91% | 37.1% |
| `ext↑, conc↑, fusion↓` | +0.28% | −0.24% | +0.88% | 37.2% |
| **`conc↑, ext↑, fusion↓`** | **+1.05%** | **+0.80%** | **+1.34%** | **23.1%** |
| `ext↑, \|cost−1\|↓, fusion↓` | +0.29% | −0.21% | +0.85% | 37.1% |
| `ext↑, \|lock−0.27\|↓, fusion↓` | +0.29% | −0.20% | +0.85% | 37.1% |

→ **conc 必须占第一优先级**才有增量；放第二位完全无效（`ext` 已决定 top3 构成，
conc 只在同 ext 的票间微调，区分度不足）。

### 关卡④ 单月压力 + 内生性 — 通过（有保留）

- 逐月（conc 优先排序 vs 基线排序）：**21/32 月为正**，中位 +1.03%，均值 +1.07%；
  剔除贡献最大 3 月后仍 **+0.58%**（对比过滤方案只剩 +0.09%）。
- 选中票活跃度：换手率中位 1.39%（基线 1.99%）、成交额中位 **2.1 亿**（基线 2.53 亿）
  → 偏低但绝对流动性健康，**不是低流动性垃圾股**。
- 内生性：换手率单独分档**非单调**（Q1 +0.86% / Q2 +1.42% / Q3 +1.01%）→ 低换手本身不是好事
  → conc 不是它的马甲。但控制换手率后，conc 的**收益**价差 2/3 桶为正（高换手桶 −0.21 反转），
  **止损率 3/3 桶单调**。

## 4. 上线方案（建议，待决策）

### 最小改动（3 处 + 1 次回填）

**① `stock_signal` 加列**
```sql
ALTER TABLE stock_signal ADD COLUMN chip_conc REAL;
```
（与 2026-09 加 `pct_above_ma20` 同一套路；`PRAGMA table_info` 取列名用索引 `r[1]`）

**② `core/sync.py::_build_signal_records`** — 落库时写入 `chip_conc`
（调用 `strategy.chip.compute_chip_factors(df, circ_shares)`，取 `conc` 末值；失败则留 NULL）

**③ `core/outcome_tracker.py::short_order_clause()`（82 行）** — 排序键加开关

```python
def short_order_clause(alias: str = "s") -> str:
    from config.strategy_params import get_param
    direction = "DESC" if int(get_param("short_ext_sort_desc")) else "ASC"
    if int(get_param("short_chip_sort_prioritize")):
        # 筹码集中优先（2026-09-15 实验：组合口径全期 +0.32%→+1.05%、
        # 样本内 -0.20%→+0.80%、样本外 +0.91%→+1.34%；止损 37.1%→23.1%，21/32 月为正）
        # COALESCE 9.9 = 历史未回填行（chip_conc IS NULL）排最后，绝不崩
        return (f"CASE WHEN {alias}.strategy = '隔日动量' THEN 0 "
                f"WHEN {alias}.strategy = '缩量回踩' THEN 1 ELSE 2 END, "
                f"COALESCE({alias}.chip_conc, 9.9) ASC, "
                f"COALESCE({alias}.pct_above_ma20, 0) {direction}, "
                f"COALESCE({alias}.fusion_score, 0) DESC")
    return (f"CASE WHEN {alias}.strategy = '隔日动量' THEN 0 "
            f"WHEN {alias}.strategy = '缩量回踩' THEN 1 ELSE 2 END, "
            f"COALESCE({alias}.pct_above_ma20, 0) {direction}, "
            f"COALESCE({alias}.fusion_score, 0) DESC")
```

**④ 新增 TUNABLE_PARAMS**：`short_chip_sort_prioritize`（int，默认 0 = 关闭，一键回滚）

**⑤ 历史回填**：`stock_signal` 历史行 `chip_conc` 需重扫填充，否则 `COALESCE` 降级到旧键。

### ⚠ 关联影响清单（改前必须确认）

| 影响面 | 说明 |
|--------|------|
| 三处出口 | `short_order_clause` 被「今日推荐 / 出场跟踪 / 复盘入库」共用 → 一处改三处变 |
| 既有回测口径 | `eval_short_observe_rule.py` 等工具的 `portfolio()` 硬编码 `ext ASC + fusion DESC` → 上线后需同步，否则新旧结论不可比 |
| 前端 | 若要展示「筹码集中度」列，改 `dashboard.html` 需同步 `?v=YYYYMMDD` 版本号 |
| 生效方式 | 后端改动**必须重启 `start.bat`**；仅前端改动硬刷新即可 |
| 端口 | 自测另起 5001（5000 常被用户自己的服务占用） |

### 建议的验证顺序

1. **影子模式**：先只落 `chip_conc` 列不回填、不改排序，观察 2~3 周填充率与 NULL 比例；
2. 回填历史后跑 `tools/eval_chip_factor.py` 复验（本报告全部结论可一键复现）；
3. 开 `short_chip_sort_prioritize=1`，**同步改 `portfolio()`** 后重跑组合口径确认；
4. 若样本外恶化 → `short_chip_sort_prioritize=0` 一键回滚（无需改代码）。

## 5. 开放问题 / 下一步

1. **为什么 conc 优先排序跟"降序/升序 ext"的关系没测**：现线上 `short_ext_sort_desc=0`（升序）。
   conc 优先会不会让 `short_ext_sort_desc` 之争变得无关？需交叉测试 4 组合。
2. **`lock` 是倒 U 型**（Q2 甜蜜区 +1.62% / 胜率 56.2%），比 conc 的单变量更强，
   但排序变体里 `|lock−0.27|↓` 无效——可能因为倒 U 型因子不适合做排序键（需要构造
   「距最优点的距离」，而 0.27 这个中点是全样本拟合的，有过拟合风险）。值得单独设计。
3. **筹码因子对出场可能比入场更有用**：上方压力大的票提前止盈，
   与「左尾 −21.33%（收盘判定 + 连续跌停穿透）」的未开放问题直接相关。
4. **`center_shift == 0` 占 5,151 条**是 log 网格分辨率伪影（p50 落在相邻档之间不移动），
   需要用更细网格或连续量重算以验证该因子的真实效力。
5. **三角形分布 vs 均匀分布**、**衰减模型**（换手率衰减 vs 时间衰减）是本模块的建模自由度，
   本轮只扫了 `decay`，未扫分布形状。
