# 2026-11-10 缺日数据事故：根因、补数留档与 P0 加固

负责人：数据/后端工程师｜批准：管理A（缓存补数属 SOP 自主范围追认）

## 事故现象

- `daily_price` 在 2026-10-29、2026-11-06 两个交易日**全市场 0 行**（相邻日各 4513~4516 行）。
- `index_daily` 额外缺 2026-10-08、2026-10-23 两天（这两天个股行情正常，指数同步单独失败）。
- `stock_signal` 缺口日 0 条：整条管线当天没跑，当天没有推荐。
- 影响面：deep_track 302 笔 closed 中 **21 笔跨 10-29 持仓**（出场结算盲一天）；
  样本外 9-11 月统计窗口受污染。MFE 策略实验（A 方案）因此被要求数据修复后复跑。

## 根因（一句）

**调度进程当天未运行（本机常驻 `python app.py` + schedule 库循环，进程不在=整天没跑），
且 `daily_sync_by_date` 只同步"当日"、无缺日追补机制，缺口永久残留。**

取证：
- `logs/` 无 `aiquant.log.2026-10-29`、`.2026-11-06` 轮转文件（10-28→10-30、11-05→11-07 连续）——排除"拉取静默失败/兜底返回空"（那会留下日志行）；
- `sync_log` 当日无记录；10-30 恢复后仅同步 `dates=['20261030']`，不回看。

## 补数过程（2026-11-09 夜）

1. 快路径 `fetch_klines_by_date` 对**历史单日不可用**（clist/hist date 参数对过去日期返回空、腾讯批量源仅当日、akshare 降级 59 页拉完仍空）——原预估"1-2 分钟/日"不成立。
2. 改用逐股东财个股 K 线 `fqt=0`（当日实际价）。补前探针：抽 50 只×相邻 4 日，DB close 与 fqt=0 返回值 200/200 逐价吻合——相邻行本就是 clist 当日快照，**与库内既有口径一致，不引入第三种价**。
3. 写入 8,490 行（10-29: 4,514｜11-06: 4,516），失败 0；指数 5 code × 4 缺日补齐（volume 手→股 ×100 与库口径一致）。
4. 验收：补数日前后环比一致性抽检 100 只 0 不一致；NULL/OHLC 违规 0；`stock_signal` 保持 0 行（管理A红线：不事后造信号）。

## 为什么必须在 review 层留档

半年后若再看到"跨 10-29 的持仓收益异常"，第一反应容易当成策略问题。
它是**数据完整性事故**，已修复且修复口径经验证；21 笔重放结果以补数后数据为准
（量化策略工程师复跑，见 1adee51 erratum）。

## P0 加固（本 commit 实现，dev 分支）

`core/data_integrity.py` + `daily_sync_by_date` 两处接线：

1. **缺日自愈** `self_heal()`：每次日同步开头，用交易日历（akshare，失败降级工作日近似）
   对近 60 日 `daily_price`/`index_daily` 覆盖率 diff，缺日自动逐股 fqt=0 补拉 + 指数补齐。
   只补行情、绝不补跑信号；单次最多补 5 日；全链异常吞掉不阻断主同步。
2. **当日行数护栏** `check_daily_row_guard()`：写库后当日行数 < 活跃股票数×90% →
   写 `risk_events`（level=critical）；`scheduler/runner.py` 同步把 sync_log 记为
   `GUARD_FAIL`（success=0、failed=行数），不再伪装成功。

测试：`tests/test_data_integrity.py` 11 项（检测/告警/字段映射/幂等/编排/降级），
既有 sync/scheduler 相关 68 项回归通过。
